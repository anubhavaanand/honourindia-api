# सम्मान · Honour India

**A billboard network for the minds that built India.**

Websites reserve corners of every page for advertisements. Honour India turns
that corner into a rotating billboard honouring Indian scientists, doctors,
engineers and mathematicians — the discoverers and quiet geniuses who are
rarely celebrated. One line of code on any site, free forever, no tracking.

```
<div data-honourindia></div>
<script src="https://your-host/embed.js" async></script>
```

That's the whole integration. A tasteful billboard fades in, rotates through
the catalogue every few seconds, links each name to their Wikipedia page, and
shows the portrait's license credit in tiny footer text.

---

## Quick start

```bash
npm install          # installs all workspaces
npm run build        # builds the embed widget
npm run seed:images  # downloads freely-licensed portraits from Wikipedia/Commons (idempotent)
npm run dev          # serve on http://localhost:3000
```

Then open http://localhost:3000 — the demo site with the live widget, a
copy-paste snippet playground, the full API docs, and the figure catalogue.

## Repository layout (npm workspaces)

```
data/
  figures.json        # the seed catalogue — 28 honoured figures
  images.json         # per-image file + credit + license (generated by seed script)
public/images/        # downloaded portraits (served at /images/*)
packages/
  embed/              # the embeddable widget → dist/embed.js (11 kb, zero deps)
apps/
  server/             # Hono API + static file server (single process)
  site/               # demo & docs homepage (plain HTML/CSS/JS)
scripts/
  fetch-images.mjs    # seeds portraits + attribution from Wikipedia/Wikimedia
```

## The embed widget

Drop the container anywhere; attributes tune it:

| Attribute       | Values                                   | Default     |
| --------------- | ---------------------------------------- | ----------- |
| `data-theme`    | `dark` \| `light`                        | `dark`      |
| `data-size`     | `rectangle` (300×250) \| `leaderboard` (728×96) \| `poster` (480×520) | `rectangle` |
| `data-interval` | seconds per billboard (5–60)             | `8`         |
| `data-api`      | override API base                        | origin of `embed.js` |

Or mount programmatically: `HonourIndia.mount('#slot', { theme: 'light', interval: 10 })`
returns `{ destroy() }`.

How it behaves:

- fetches a **batch** of billboards once and rotates client-side — no server
  round-trip per rotation, so it scales to any traffic;
- renders inside a **shadow root** — host page styles cannot clash with it;
- pauses when the tab is hidden, restarts when visible;
- respects `prefers-reduced-motion` (no auto-rotation);
- figures without a freely-licensed portrait get an elegant monogram card;
- only ~11 kb minified, no dependencies, works back to ES2018 browsers.

## The API (v1)

Open CORS on everything, JSON only, cache-friendly, light rate limiting
(120 req/min per IP).

| Endpoint | Description |
| --- | --- |
| `GET /api/v1` | Endpoint index and mission. |
| `GET /api/v1/billboards/random?count=8` | Random billboards for widgets (`count` 1–24). |
| `GET /api/v1/figures` | The full catalogue (summaries). |
| `GET /api/v1/figures/:slug` | One figure in full — summary, quote, links. |
| `GET /api/v1/whoami` | Your tier (anonymous/keyed) and rate-limit budget. |
| `GET /api/v1/meta` | Dataset size and licensing metadata. |
| `GET /embed.js` | The widget script itself. |
| `GET /healthz` | Liveness probe. |

### API keys (optional)

The API is **keyless by default** — the embed works for anyone, forever. Keys
exist for partners and heavy consumers:

| Tier | Limit | Scope |
| --- | --- | --- |
| Anonymous (no key) | 120 req/min | per IP |
| Keyed | 1,200 req/min | per key |

```bash
npm run issue-key -- --name "Partner App"   # prints the key ONCE
curl -H "Authorization: Bearer hi_…" https://host/api/v1/whoami
curl "https://host/api/v1/billboards/random?count=8&key=hi_…"   # also accepted
```

Keys are stored **only as sha-256 hashes** in `data/keys.json` (safe to
commit — the plaintext is shown once at issuance and never stored). Embedders
can pass `data-key="hi_…"` on the billboard container to use a key from the
widget. Restart the server after issuing keys.

Example billboard:

```json
{
  "slug": "anna-mani",
  "name": "Anna Mani",
  "years": "1918–2001",
  "field": "Physics · Meteorology",
  "tagline": "Insisted India build its own weather instruments…",
  "quote": null,
  "image": {
    "url": "/images/anna-mani.jpg",
    "credit": "Rajasekharan Parameswaran",
    "license": "CC BY-SA 4.0"
  },
  "link": "https://en.wikipedia.org/wiki/Anna_Mani"
}
```

## Data & licensing policy

- Facts about people are not copyrightable; the catalogue lives in
  `data/figures.json` and anyone may extend it via pull request.
- **Only freely-licensed portraits are served.** The seed script records each
  image's author and license from Wikimedia metadata, and four figures whose
  only available images were *fair-use* (Asima Chatterjee, G. N. Ramachandran,
  G. D. Naidu, Raj Chandra Bose) intentionally show monograms until someone
  contributes a free portrait. Fair-use images must not be redistributed
  through this API.
- The widget displays `credit · license` on every billboard — embedders agree
  to preserve that attribution by using the widget.

### Adding a figure

1. Add an entry to `data/figures.json` (slug, name, born/died, field, tagline,
   summary, optional quote, exact `wiki` page title).
2. Run `npm run seed:images` — it picks up the article's lead image and license,
   or an explicit `commonsFile` override if the article has no flagged portrait.
3. Restart the server (the catalogue is loaded at boot for speed).

## Deployment

Single stateless Node process (≥ 20) — no database, no secrets. `PORT`
(default 3000) is the only configuration.

**Render (one click):** the repo ships a `render.yaml` Blueprint. In Render:
*New + → Blueprint* → select the repo → apply. The build compiles both
workspaces (`esbuild` for the widget, `tsc` for the server) and the service
then runs plain Node — production runtime needs only the `dependencies`, so
`NODE_ENV=production` is safe. Health check: `/healthz`. Note the free tier
sleeps after idle; the widget's retry loop transparently recovers on wake.

**Any platform or VPS:**

```bash
npm install       # dev deps are needed for this step
npm run build     # esbuild → packages/embed/dist/embed.js · tsc → apps/server/dist
npm start         # node apps/server/dist/index.js
```

All build tooling runs during `npm run build` only; the running server is
plain JavaScript. Put Cloudflare in front for TLS and extra caching — the
heavy cache headers already live on `/embed.js`, `/images/*`, and the
catalogue endpoints.

**GitHub Pages edition (free static hosting):** `npm run deploy:pages` builds
a fully static mirror into `dist-pages/` and force-publishes it to the
`gh-pages` branch. Because the dataset itself is static, the mirror serves
the API's JSON at the documented paths — `/api/v1/billboards/random`,
`/api/v1/figures`, `/api/v1/meta` — as pre-generated files, and the widget
shuffles batches client-side so rotation stays random per visitor. A static
host cannot provide per-request randomness or `/api/v1/figures/:slug`
detail responses; everything else, including third-party embedding, works
with no server at all.
